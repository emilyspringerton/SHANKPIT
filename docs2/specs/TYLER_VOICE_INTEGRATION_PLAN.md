# MODE_TYLER voice: playback + integration plan (pre-rendered clips first, PARENA synth later)

Founder real-time, 2026-10-01: ensure TYLER/MODE_TYLER affordances, VALHANNA voices via TTS. Output of the 2026-10-01 TTS feasibility investigation (workflow wf_853cfa47-f7d, investigator T-D), including a scratch prototype that passed 43 assertions against the real tyler_coldopen.c/story_ai.c. Decision: ship pre-rendered Piper clips now (labeled stopgap), design the seam so the PARENA-native synth drops in later.

## Summary

Nothing in the voice path is reachable today: the lobby has no TYLER tile and never calls tyler_coldopen_start/tick, and the dedicated server's REFLUX log is invisible to clients. Two verified blockers sit ahead of any audio work. (1) story_ai_tick early-returns outside MODE_STORY, so Tyler and Hana get zero movement input in MODE_TYLER. (2) audio.c is a fixed 12-sound, 22.05 kHz stereo wavetable bank with no loader, no per-frame re-pan and no bus or ducking. The design below adds zero new .c files, which avoids the CI source-list drift (documented in release.yml as 7 recurrences, plus tyler_voice_mod.c as an 8th in d50e514). Pieces: (a) PARENA tyler/voice-mod gains 4 pure decision functions, regenerated into the existing tyler_voice_mod.c; (b) tyler_coldopen.{h,c} gains a lines table, a state view and a pure edge-driver; (c) a header-only packages/audio/vo_mix.h holds the SDL-free mixer core; (d) audio.c/.h gain a VO bus API; (e) a new 24-byte PACKET_TYLER_BEAT (13), modeled on PACKET_WORLD_CLOCK, carries whole-state beat plus elapsed ms; (f) eight 22.05 kHz mono WAVs (about 1.07 MiB) ship under assets/tyler_vo/, which the Windows zip already copies via cp -r assets; (g) a LOBBY_TYLER tile and a pause-menu VOICE toggle. I built a scratch prototype of the PARENA additions, the driver and a two-bus ducking mixer, and ran it against the REAL tyler_coldopen.c and story_ai.c on a simulated 16 ms clock: all 43 assertions pass. No repo file was modified; all output is under the scratchpad.

## Verified facts

- VERIFIED by reading packages/audio/audio.c in full: SAMPLE_RATE 22050, NUM_CHANNELS 2 (S16 stereo), BUFFER_FRAMES 512, MAX_SOUNDS 12 (static g_snd[]: 0-5 weapons, 6-10 pentatonic footsteps, all synthesized at audio_init), MAX_MIX 16. play_sound(snd_id,lgain,rgain) fixes gains at trigger time, and if all 16 voices are busy it steals the furthest-along one. There is no streaming API, no file loader, no bus or ducking, and no per-frame re-pan. The audio_callback has two separate mix paths (NOCK master-chain float path and a legacy int16 saturating path). audio_play_* are no-ops when g_dev is 0 (no audio device, e.g. plain Xvfb). audio.h exposes only audio_init, audio_shutdown, audio_play_weapon, audio_play_footstep and audio_set_master_chain. In the lobby, audio_init() is called at apps/lobby/src/main.c:10219, before the window is created.
- VERIFIED spatial law (spatial_gains in audio.c): vol = 1/(1+d^2*0.0001), pan = sin(rel_angle), L = vol*(1-max(pan,0)), R = vol*(1-max(-pan,0)). At about 10 m (the cold-open room scale) vol is about 0.99, so there is no real distance cue, and a source at 90 degrees silences the opposite channel entirely (hard pan). That is poor for speech, so the VO bus needs its own softer law (INFERENCE from the formula; not listened to).
- VERIFIED: the lobby already plays footsteps for every animated player including NPC bots (main.c:~5018 audio_play_footstep from the run-cycle code), so Tyler and Hana walking will emit pentatonic pings under the dialogue. ## Risks

- P0 BLOCKER, verified: story_ai.c:1119 gates story_ai_tick to MODE_STORY, so in MODE_TYLER the actors never get movement input (server and local). Voice will play over standing actors and the speaker position will not change.
- P0 for local play: local_game.h has no MODE_TYLER branch (local_init_match, the story_ai_tick call at ~1828, the bespoke NPC movement branch at ~1887 and the dead-state skip at ~1841 are all story-mode-gated), so local NPCs would run bot_think combat AI. The lobby never starts or ticks the coordinator and has no tile.
- P0 for net play (inference from absence of code): the cold open starts at server level load, not on first join, so a client connecting to a --tyler server after boot lands in CONSTRUCT having missed everything. Needs restart-on-first-human-join and reset-on-last-leave.
- Packaging drift: any new .c under packages/ must be added to four hand-copied source lists or the Windows/Linux link fails (8 documented recurrences including tyler_voice_mod.c). Mitigation is the zero-new-.c design: header-only vo_mix.h plus functions added to the already-listed tyler_coldopen.c, tyler_voice_mod.c and audio.c. If a .c is unavoidable, add it to all four lists in one commit and add a CI guard that derives the lists from the Makefile.
- Regression risk in the live weapon audio path if audio_callback is refactored into audio_mix_into: the legacy int16 path clamps per voice while a float path clamps once, so overlapping loud voices can differ by rounding or clipping. Mitigate with an offline parity render of the existing 11 bank sounds through old and new paths (must match within 1 LSB when no VO is active) before replacing the callback.
- Asset/table drift: clips are re-rendered nondeterministically, so durations change run to run. A re-render without regenerating tyler_voice_lines.h silently breaks hold fit and mid-line cutoffs. Needs the committed-WAV rule plus a CI check (WAV duration within 1 ms of table) and a sha256 manifest.
- Subtitle/VO text mismatch in beat 0 (VO has an extra unsubtitled sentence). The HUD table and the audio table should come from one generated source (the TSV), or subtitles will contradict the voice.
- Windows path: assets are loaded cwd-relative. PLAY.bat and double-click both start in the exe folder so it works, but a shortcut with a different working directory would silently drop every asset including the new clips. Low risk; consider an SDL_GetBasePath fallback in the loader.
- UDP loss and late join: a one-shot beat packet would drop audio permanently. The whole-state, idempotent packet at snapshot cadence and the seek-on-first-sight driver fix this (tested). Remaining client error is one-way latency plus up to one snapshot interval (about 32 ms), acceptable for VO.
- Pause-menu space: only one more item fits without moving the panel. A SUBTITLES toggle would need the panel and footer enlarged.
- The IDUNA server-driven menu path (ui_use_server, main.c:10336 and lobby_menu_entry_id) maps entries by ids from IDUNA. A new 'mode.tyler' entry would not exist there. I did not find IDUNA's menu definition (grep for mode.story_cave in IDUNA found nothing), so this is unverified and should be checked.
- Local mode level source: lobby_start_story_mode-style loading fetches from the live IDUNA registry (level_boxes_fetch_export, ids 24 Iceland and 23 CONSTRUCT), so an offline machine could not start the mode. The bundled JSONs live only in examples/, which is not shipped.
- Headless CI cannot exercise a real audio device (Xvfb has none, audio_init leaves g_dev 0). Device-level playback can only be smoke-tested with SDL_AUDIODRIVER=dummy plus a log assertion, so the real assertions must sit at the pure mixer/driver level.
- PARENA-native TTS long-term: playback seam is audio_clip_from_pcm16(), so a future in-process PARENA synth skips files entirely. Shipping synthesis at first launch is not viable near-term (about 63 MB ONNX per voice, Python or onnxruntime dependency today, unproven C inference speed). Only pre-rendered assets should ship.

## Recommendations / design

- DECISION (asset delivery): pre-render once, commit, ship. 8 mono PCM16 22050 Hz WAVs in SHANKPIT/assets/tyler_vo/vh01_b{beat}_{actor}.wav plus a manifest with sha256. Do not LZ4 per clip (measured 5.3 percent saving, 59 KB), since deflate in the release zip already handles transport; this is a measured, considered exception to the LZ4-default convention, to be noted in SHANKPIT/CLAUDE.md. No first-launch or live synthesis. The server needs no clips, only the compiled table. Resident cost is about 1.1 MB mono, 2.2 MB if stereo-expanded, so no streaming API is needed.
- TYLER/tts/render_vh01.py changes (stopgap generator, retired later): resample every clip to 22050 mono offline; compute each line's offset (beat 0: Tyler 0, Hana 2305+300=2605; all others 0) and dur_ms; emit tyler_voice_lines.h (beat, speaker, offset_ms, dur_ms, file) alongside the existing g_tyler_voice_clip_ms (which must equal max(offset+dur) per beat, tested); emit the subtitle text from the same TSV so HUD and VO cannot diverge (fixing the beat 0 mismatch); copy WAVs to SHANKPIT/assets/tyler_vo/. PARENA-first follow-up for the resampler: add stdlib/media/resample.prn (2:1 FIR decimate, with tests against the numpy result) and let it replace the Python step. Also move examples/tyler-valhanna/{tyler_1986_iceland,construct}.json to assets/tyler_levels/ and load with level_boxes_load_from_file as the offline path, preferring the live registry fetch.
- P0 fixes before any audio (each is a one-line gate plus a test): story_ai.c:1119 to accept MODE_TYLER; local_game.h local_update (~1828, ~1887, ~1841) to treat MODE_TYLER like story for story_ai_tick and NPC movement, and add a MODE_TYLER branch to local_init_match (story_phase PLAYING, num_players 1). Add a test asserting Tyler's in_fwd is nonzero during a travel beat in MODE_TYLER (the v1 harness is the starting point).
- PARENA (core deps first): extend PARENA/stdlib/tyler/voice_mod.prn with on-tyler-voice-line-state, on-tyler-voice-seek-ms, on-tyler-duck-target-permille, on-tyler-duck-step-permille (scratch prototype compiles; see deliverables) and add them to tests/test_tyler_voice.c (make test-tyler-voice). Regenerate packages/simulation/tyler_voice_mod.c with parena build. No new compile unit because tyler_voice_mod.c is already in every source list. Tuned constants from the prototype: duck target 350 permille, attack 50 ms, release 400 ms, 500 ms hold so Tyler-to-Hana's 300 ms gap does not pump.
- tyler_coldopen.h/.c additions (SDL-free, compiled into both server and lobby): typedef TylerVoiceLine {int beat; TylerActor speaker; unsigned offset_ms, dur_ms; const char *file;} with g_tyler_voice_lines[]/g_tyler_voice_line_count defined from the generated header; typedef TylerBeatView {int beat; unsigned beat_elapsed_ms; int done; int tyler_slot, hana_slot;} with void tyler_coldopen_get_view(const TylerColdOpenState*, unsigned now_ms, TylerBeatView*), which must report the previous beat while !beat_triggered so elapsed is never measured against a stale beat_started_ms; typedef TylerVoiceCmd {int line_index; unsigned seek_ms; int speaker_slot;}, TylerVoiceDriver {int last_beat; unsigned started_mask;}, tyler_voice_driver_reset(), and int tyler_voice_driver_step(TylerVoiceDriver*, const TylerBeatView*, TylerVoiceCmd *out, int max, int *stop_all). The driver marks 'over' lines as started so a late joiner never replays them, ignores repeats, and sets stop_all on a beat jump greater than 1 or on done. Working reference implementation: scratch proto/tyler_voice_proto.{h,c}.
